# Archive Report: Crate Removal (Change 018, Migration Plan Phase 8)

## Status

Shipped. All 24 tasks in `tasks.md` complete (`[x]`). Merged into `develop` via PR #54. This is the final phase of the `telemetry-transport-contract` consolidation ADR-008 scoped as Phases 3–8.

## What shipped

- Deleted `sampling.rs`, `redaction.rs`, `rotation.rs` from the orphaned `telemetry-transport-contract` crate — behavior already absorbed into `kitlogger-sampling`, `kitlogger-redaction`, `file-exporter` (changes 013/014).
- Relocated `Transport`, `DeliveryMode`, `TransportResult`, `TransportError` into a new `telemetry-adapter-contracts::transport` module — executing change 017's deferred Phase 7 handoff ("input to `telemetry-adapter-contracts`'s own future roadmap, not executed here"; nobody had picked it up since). `Transport`/`DeliveryMode`/`TransportResult`/`TransportError` are an optional toolkit, not part of the `Adapter` supertrait — `console-exporter`/`file-exporter` have no wire protocol to abstract over and never depend on it. `TransportError` stays distinct from `AdapterError`: different failure domains (wire-level delivery vs. registry/lifecycle management).
- Ported the crate's own 3 unit tests into the new location.
- Deleted `crates/telemetry-transport-contract/` entirely (source, `Cargo.toml`) and removed it from the workspace root `Cargo.toml`.
- Formally superseded `openspec/specs/exporter-registry/spec.md`: all 3 requirements (Exporter Selection by Name, Exporter Registration, Default Exporter) removed, each with a reason pointing to the requirement in `output-adapter-contracts` that actually covers the concern. The file is kept (not deleted) as a record that this capability was proposed and superseded, per OpenSpec convention.
- Created `openspec/specs/telemetry-adapter-contracts/spec.md` — the first canonical, OpenSpec-format spec for this capability's `transport` addition (its pre-existing surface — `Adapter`, `ExporterAdapter`, `AdapterRegistry`, `mapping.rs`, etc. — remains specified in the older, pre-OpenSpec convention at `specs/archive/2026-06-19-002-core-telemetry-domain-model-as-03-telemetry-adapter-contracts/`, out of scope here).

## Premise correction, found and fixed before implementation

The proposal originally listed eight modules as still needing deletion (`formatter.rs`, `output.rs`, `sampling.rs`, `redaction.rs`, `rotation.rs`, `buffering.rs`, `provider.rs`, `logger.rs`), carried over from ADR-008's original Phase 8 description. Verified against the actual tree before touching any code: change 016 had already deleted five of the eight (`formatter.rs`, `output.rs`, `buffering.rs`, `provider.rs`, `logger.rs`). Only `sampling.rs`, `redaction.rs`, `rotation.rs` remained. `proposal.md`, `design.md`, and `tasks.md` were corrected to the real scope (three modules, not eight) before implementation began — the same discipline applied to changes 016 and 017's own premise corrections earlier in this migration. `tasks.md`'s task 3.4 also had two stale test names (`test_backpressure_signal`, already replaced by change 017 with `backpressure_variant_survives_the_canonical_type_repoint`) — corrected to name the tests that actually existed at the time of porting.

No architectural conclusion changed as a result — only which files needed touching.
